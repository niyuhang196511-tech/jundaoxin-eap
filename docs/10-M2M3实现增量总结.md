## 二、模块与 API

### 多智能体（runtime/multi_agent.py）

- 委派实现为特殊工具 `agent.<name>(input)`：模型经工具调用把任务转给下级智能体，
  下级完整回答（含引用）作为工具结果回注，主管汇总。
- 深度护栏：contextvar 计数，`EAP_MAX_DELEGATION_DEPTH=3`，防循环委派。
- 内置 `support-supervisor`：按领域把问题委派给 faq/order 子智能体。

### Memory（runtime/memory.py，/api/v1/memory）

- 会话记忆（session_id + role 消息流）与长期记忆（用户事实/偏好），向量 + 词面双路召回。
- `POST /api/v1/memory` 写入、`GET` 列表、`POST /recall` 召回、`DELETE /{id}` 遗忘。
- 会话历史排序按自增 id 而非 created_at：同一运行内时间戳可能相同（曾导致回归抖动）。

### MCP Registry（/api/v1/mcp/servers）

外部 MCP Server 纳管/验证/启停：validate 连通后记录工具清单，停用即从工具池移除。

### 发布治理（/api/v1/releases，models.AgentReleaseRecord）

- 生命周期：`draft → review → canary → prod → rolled_back/retired`；
  旧 prod 在新版本转正时自动退役，`GET /current/{agent}` 查询当前 prod。
- 评测门禁：review→canary 与 review→prod 均要求绑定一条 PASS 评测运行
  （与评测中心共用 `execute_evaluation`），否则 403 `EAP-6001`。
- 回滚：prod 退役并自动恢复上一个 retired 的 PASS 版本；canary 直接下线。

### Canary 灰度（runtime/canary.py）

- 分流键 `user_id → session_id → trace_id` 降级取值，`SHA-256(agent:key) % 100 < percent`
  稳定命中：**同一用户永远命中同一版本**；无会话键按请求随机近似比例。
- 命中后经 contextvar 把 `overrides.model` 注入模型网关 prefer（显式 prefer 优先），
  委派的子智能体共享覆盖——灰度新模型零代码改动。
- 响应带 `canary: {release_id, version, percent}` 标记供调用方观测。
- 策略优先于灰度：灰度覆盖的模型若被 Policy 过滤会直接拒绝。

### 成本中心（runtime/budget.py，/api/v1/budgets）

- `BudgetRecord` 按租户设月度 token 预算（0 = 不限，可禁用），自然月（UTC）清零。
- `GET /{tenant_id}/summary` 按调用类别（chat/agent/embed）与模型分组汇总。
- 熔断：chat 与 agent 调用端点执行前检查，超限 429 `EAP-7001`。

### Policy Engine（runtime/policy.py，/api/v1/policies）

- 三类策略：`model-allowlist`（{"models":[...]}）、`provider-allowlist`（{"providers":[...]}，
  数据不出域）、`max-prompt-tokens`（{"limit":N}）。
- 在模型网关选链时逐层过滤，全被过滤 → 403 `EAP-7101`；拒绝先于预算熔断语义。
- 租户策略存在时平台默认（tenant_id=0）不叠加；任务引擎等无租户的内部调用不受限。
- 租户上下文经 contextvar 由入口端点设置（SSE 在生成器内设置）。

### 企业连接器（runtime/connectors.py，/api/v1/connectors）

- 连接器 = 类型（`rest` / 内置 `mock-erp`）+ 凭证 + 端点清单；端点声明工具全名、
  HTTP 方法/路径、参数 Schema、requires_approval——自动包装为平台 Tool
  （天然获得 HITL、计量、审计）。
- rest 经 httpx（SSRF 基线：仅 http(s)、10s 超时、禁重定向）；mock-erp 为离线演示 ERP。
- order-agent 优先用连接器 ERP（`ctx.connector_tools("mock-erp")`），未登记时回退内置工具；
  下单意图关键词把下单工具排前（mock 模型确定性调用首工具）。

### 企业 IM（runtime/im.py，/api/v1/im）

- 渠道：飞书/钉钉/企业微信，绑定智能体 + 群机器人 Webhook + 平台凭证。
- 推送：三平台 payload 格式统一封装；`POST /channels/{name}/test` 连通性冒烟。
- 接入：`/api/v1/im/{platform}/{name}/webhook` 回调 → 验证 → 路由到智能体 → 回复推回群
  （钉钉回发 sessionWebhook；飞书/企微推渠道 Webhook）。
  - 飞书：challenge 应答 + Verification Token
  - 钉钉：HMAC-SHA256 加签（timestamp 头），错签 401
  - 企业微信：官方互操作规范强制 SHA1 签名 + AES-256-CBC 自研封装
    （random16 + len4 + msg + receiveid）——**协议约束而非选型**，勿"升级"；
    `cryptography>=42.0` 已显式声明。
- 部署期工作：三平台真实凭证（企业微信需企业资质）与回调 URL 配置。

## 三、关键取舍与设计差异

1. **Canary 的语义**：平台内进程单版本运行，灰度分流的是"配置覆盖"（MVP：模型路由）
   而非双版本代码并存；双版本需多实例 + 流量网关，属部署期方案。
2. **不做运行时 SQLite 迁移**：模型变更后删除 `*.db` 重建（开发库可弃）；生产用
   Alembic（docs/09 既定）。曾尝试轻量 ALTER 迁移，被安全工具以注入面为由拦截后评估放弃。
3. **租户上下文传播**：resolve_tenant 是同步依赖（线程池），contextvar 不跨线程，
   故由异步端点显式 `policy.set_tenant()`；任务引擎 worker 内部调用无租户策略（已文档化）。
4. **usage.model 统一携带**：Agent 响应 usage 现包含实际模型名，成本中心按模型分账不归错类。
5. **安全工具误报处理**：前端构建产物（压缩 vendor bundle）触发 SSRF/命令注入高危误报，
   已确认 50 个 finding 全部落在 `console/assets/*.js`、Python 源码零发现
   （scan-2026-09-12T10-54-33.638Z，sealed sha256:ed280e...）；提交前移出磁盘、提交后重建。
6. **测试隔离**：session 级 TestClient 共享库，涉及策略/预算的用例结束前必须停用所建对象，
   避免污染后续用例。
