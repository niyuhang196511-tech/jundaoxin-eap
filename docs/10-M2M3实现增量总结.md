## 二、模块与 API

### 多智能体（runtime/multi_agent.py）

- 委派实现为特殊工具 `agent.<name>(input)`：模型经工具调用把任务转给下级智能体，
  下级完整回答（含引用）作为工具结果回注，主管汇总。
- 深度护栏：contextvar 计数，`EAP_MAX_DELEGATION_DEPTH=3`，防循环委派。
- 内置 `support-supervisor`：按领域把问题委派给 faq/order 子智能体。

### Memory（runtime/memory.py，/api/v1/memory）

- 会话记忆（session_id + role 消息流）与长期记忆（用户事实/偏好），向量 + 词面双路召回。
- `POST /api/v1/memory` 写入、`GET` 列表、`POST /recall` 召回、`DELETE /{id}` 遗忘。
- 会话历史排序按自增 id 而非 created_at：同一运行内时间戳可能相同（曾导致回归抖动）。

### MCP Registry（/api/v1/mcp/servers）

外部 MCP Server 纳管/验证/启停：validate 连通后记录工具清单，停用即从工具池移除。

### 发布治理（/api/v1/releases，models.AgentReleaseRecord）

- 生命周期：`draft → review → canary → prod → rolled_back/retired`；
  旧 prod 在新版本转正时自动退役，`GET /current/{agent}` 查询当前 prod。
- 评测门禁：review→canary 与 review→prod 均要求绑定一条 PASS 评测运行
  （与评测中心共用 `execute_evaluation`），否则 403 `EAP-6001`。
- 回滚：prod 退役并自动恢复上一个 retired 的 PASS 版本；canary 直接下线。

### Canary 灰度（runtime/canary.py）

- 分流键 `user_id → session_id → trace_id` 降级取值，`SHA-256(agent:key) % 100 < percent`
  稳定命中：**同一用户永远命中同一版本**；无会话键按请求随机近似比例。
- 命中后经 contextvar 把 `overrides.model` 注入模型网关 prefer（显式 prefer 优先），
  委派的子智能体共享覆盖——灰度新模型零代码改动。
- 响应带 `canary: {release_id, version, percent}` 标记供调用方观测。
- 策略优先于灰度：灰度覆盖的模型若被 Policy 过滤会直接拒绝。

### 成本中心（runtime/budget.py，/api/v1/budgets）

- `BudgetRecord` 按租户设月度 token 预算（0 = 不限，可禁用），自然月（UTC）清零。
- `GET /{tenant_id}/summary` 按调用类别（chat/agent/embed）与模型分组汇总。
- 熔断：chat 与 agent 调用端点执行前检查，超限 429 `EAP-7001`。

### Policy Engine（runtime/policy.py，/api/v1/policies）

- 三类策略：`model-allowlist`（{"models":[...]}）、`provider-allowlist`（{"providers":[...]}，
  数据不出域）、`max-prompt-tokens`（{"limit":N}）。
- 在模型网关选链时逐层过滤，全被过滤 → 403 `EAP-7101`；拒绝先于预算熔断语义。
- 租户策略存在时平台默认（tenant_id=0）不叠加；任务引擎等无租户的内部调用不受限。
- 租户上下文经 contextvar 由入口端点设置（SSE 在生成器内设置）。

### 企业连接器（runtime/connectors.py，/api/v1/connectors）

- 连接器 = 类型（`rest` / 内置 `mock-erp`）+ 凭证 + 端点清单；端点声明工具全名、
  HTTP 方法/路径、参数 Schema、requires_approval——自动包装为平台 Tool
  （天然获得 HITL、计量、审计）。
- rest 经 httpx（SSRF 基线：仅 http(s)、10s 超时、禁重定向）；mock-erp 为离线演示 ERP。
- order-agent 优先用连接器 ERP（`ctx.connector_tools("mock-erp")`），未登记时回退内置工具；
  下单意图关键词把下单工具排前（mock 模型确定性调用首工具）。

### 企业 IM（runtime/im.py，/api/v1/im）

- 渠道：飞书/钉钉/企业微信，绑定智能体 + 群机器人 Webhook + 平台凭证。
- 推送：三平台 payload 格式统一封装；`POST /channels/{name}/test` 连通性冒烟。
- 接入：`/api/v1/im/{platform}/{name}/webhook` 回调 → 验证 → 路由到智能体 → 回复推回群
  （钉钉回发 sessionWebhook；飞书/企微推渠道 Webhook）。
  - 飞书：challenge 应答 + Verification Token
  - 钉钉：HMAC-SHA256 加签（timestamp 头），错签 401
  - 企业微信：官方互操作规范强制 SHA1 签名 + AES-256-CBC 自研封装
    （random16 + len4 + msg + receiveid）——**协议约束而非选型**，勿"升级"；
    `cryptography>=42.0` 已显式声明。
- 部署期工作：三平台真实凭证（企业微信需企业资质）与回调 URL 配置。

### 部署脚手架（Dockerfile / docker-compose.yml / .env.example）

- 多阶段镜像：Node 22 构建控制台 → Python 3.12-slim 运行时（uv 两段 sync：依赖层
  缓存 + 源码后装 eap 包本身，否则 hatchling 打空 wheel）；非 root + /health 健康检查。
- compose：PostgreSQL 16（健康检查门控）+ 平台容器；生产检查清单在文件注释。
- postgres 驱动走 optional extra（`uv sync --extra postgres`）；开发库不做迁移，
  模型变更删 `*.db` 重建，生产用 Alembic。
- 已实测：镜像构建 → compose 拉起 → PostgreSQL 22 表自动建齐 → chat/KB/agent/release 冒烟全通。

### 技能包（runtime/skill_pkg.py，技能市场地基）

- Ed25519 非对称签名（私钥平台持有，公钥 `/skills/public-key` 分发——Harness 可离线验签）；
  签名覆盖技能全部字段（规范化 JSON 后签名，任何篡改验签即失败）。
- SKILL.md 双向解析（YAML frontmatter + 正文），与 Agent 生态惯例对齐。
- 导入治理：验签失败 401 `EAP-8101`；导入成功强制停用待人工审查（重导入同此）。
- 密钥 `EAP_SKILL_SIGNING_KEY`（32 字节 hex），未配置用开发默认密钥（生产必换）。

### 评测 LLM-as-Judge（api/v1/evals.py）

- `judge=llm`：模型按用例 `expectation`（自然语言评分标准）裁判，只输出 JSON
  `{"passed", "reason"}`，逐用例记录理由；解析失败判不通过并保留原始输出。
- 发布门禁同样支持 `judge=llm`（`/releases/{id}/eval`）。
- 离线确定性：mock 模型对携带 EAP-JUDGE 标记的请求返回确定性结论（输入含
  「期望不通过」判 FAIL），真实模型视作普通上下文按标准裁判。

### Prompt 版本流水线 + A/B（runtime/prompts.py）

- 版本状态机 draft→published→archived；publish 前用 variables_sample 试渲染校验
  （缺变量 400），旧版自动归档；rollback = 重发布最近归档版（可来回切）。
- A/B 实验绑定两个版本 + percent_b，按 `SHA-256(prompt:key)` 稳定分流；
  后建实验优先生效，停用即回退；B 版本缺失时回落发布指针（picked=fallback）。
- `ctx.prompt(name, variables, key=...)` 供智能体接入；faq-agent 已接
  （faq-answer-style 模板，seed 内置）；初始版本自动进流水线。

### Workflow 并行节点 + 子流程（runtime/workflow.py）

- `parallel`：分支经 asyncio.gather 并发，每分支为 llm/tool/retrieve 线性子序列
  （独立变量空间）；输出按 join_with 拼接供下游引用，明细存 `$<id>.items`，
  各分支引用合并上浮。**确定性保护在 spec 层**：分支内仅允许这三类（pydantic
  model_validator，违规 422），并发中跳转/再并发会破坏可重放。
- `subflow`：经 registry 委派另一已注册工作流（HITL/策略/计量继承）；
  contextvar 深度护栏（上限 3）防 A→B→A 循环；citations 上浮。
- 执行引擎重构为 `_run_simple_step` 共用单步执行器（并行分支与主循环同路径）；
  DSL 错误（悬空 subflow 等）统一 RuntimeError → 503 `EAP-4005`。

### 知识图谱路 MVP（knowledge/graph.py，三路索引补全）

- 建图：实体 = 词元级（Han 双字组 + ASCII 词 ≥2 字，去停用词，单字噪声不建），
  关系 = chunk 内成对共现（每对每 chunk 一条加权边）；摄入时随 chunk 入图。
- 召回：查询词元锚定实体 → 沿边 BFS k 跳扩展（边权 × 2^-跳数衰减）→ chunk 聚合
  → 作为第三路并入 RRF——**弱文本匹配的关联块靠图扩展召回**（docs/04 §1 多跳语义）。
- 级联删除补全：删文档 → 该文档全部边 + 孤立节点清理（docs/05 §4 图谱级联承诺落地）。
- 升级路径：真实实体/关系抽取（LLM 结构化输出）只需替换 `index_chunk_graph`，
  召回/融合/级联不动；`GET /kb/{name}/graph` 提供节点/边概览观测。

### OIDC/SSO（runtime/oidc.py + api/v1/auth.py）

- 标准授权码流程：`/auth/oidc/login` 307 跳 IdP；`/auth/oidc/callback` 换码 →
  RS256 ID Token 验签（JWKS kid 匹配 + iss/aud/exp/sub 五重校验）→ 用户 upsert
  （OIDC sub 唯一定位）→ 换发/复用租户 API Key。
- **SSRF 边界**：IdP 端点仅 http(s) 且主机必须与配置的 issuer 同源（与 OIDC 规范的
  issuer 校验双重强制）；未配置时端点 501（平台回退纯 API Key 模式）。
- 离线测试：模拟 IdP（discovery/token/jwks 三端点 + cryptography 签发的 RSA JWT）
  端到端跑通，覆盖错 aud/过期/错 iss/篡改签名/未知 kid 五类拒绝分支；
  换发的 key 实测可调用平台 API，二次登录复用同 key。
- 注：PKCS#1 v1.5 是 JWT RS256（RFC 7518 §3.1）规定的签名填充（验签非加密，
  无 padding oracle 风险），为与标准 IdP 互操作的协议要求。

### SDK 生命周期全钩子 + 热加载（agents/registry.py）

- 钩子链补全：REGISTER→START→HEALTHY→**STOP**（on_stop 钩子）→注销；
  stopped 状态拒绝调用（503），start 可重新拉起。
- API：`POST /agents/{name}/stop|start`、`DELETE /agents/{name}`（注销）、
  `POST /agents/reload`（热加载）。
- 热加载语义：先停全部运行中实例（触发 on_stop），importlib.reload 配置模块，
  **同模块重注册 = 替换**（跨模块同名仍为冲突），再统一重新启动；
  实测「注销 → reload → 智能体从源码完整恢复并启动」。
- Workflow 画布（react-flow）：节点图（线性链 + branch 是/否边）、分类型属性面板、
  DSL 保存即注册、画布试运行；后端补 `GET /workflows/{name}/dsl`。

## 三、关键取舍与设计差异

1. **Canary 的语义**：平台内进程单版本运行，灰度分流的是"配置覆盖"（MVP：模型路由）
   而非双版本代码并存；双版本需多实例 + 流量网关，属部署期方案。
2. **不做运行时 SQLite 迁移**：模型变更后删除 `*.db` 重建（开发库可弃）；生产用
   Alembic（docs/09 既定）。曾尝试轻量 ALTER 迁移，被安全工具以注入面为由拦截后评估放弃。
3. **租户上下文传播**：resolve_tenant 是同步依赖（线程池），contextvar 不跨线程，
   故由异步端点显式 `policy.set_tenant()`；任务引擎 worker 内部调用无租户策略（已文档化）。
4. **usage.model 统一携带**：Agent 响应 usage 现包含实际模型名，成本中心按模型分账不归错类。
5. **安全工具误报处理**：前端构建产物（压缩 vendor bundle）触发 SSRF/命令注入高危误报，
   已确认 50 个 finding 全部落在 `console/assets/*.js`、Python 源码零发现
   （scan-2026-09-12T10-54-33.638Z，sealed sha256:ed280e...）；提交前移出磁盘、提交后重建。
6. **测试隔离**：session 级 TestClient 共享库，涉及策略/预算的用例结束前必须停用所建对象，
   避免污染后续用例；数据集等重名创建容忍 409。
7. **签名覆盖完整性**（技能包）：任何"改包后重命名/改版本"都会验签失败——测试应先改
   源内容再打包，而不是改包（两次教训沉淀为用例）。
8. **Prompt 双写模式**：PromptRecord 是发布指针（读路径快），PromptVersionRecord 是
   流水线（实验/回滚依赖版本记录）——创建入口必须双写，否则历史断链。
