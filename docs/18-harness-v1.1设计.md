# 18 - Harness 桌面端 v1.1 设计方案（待批准）+ 组织记忆联动 KB

> **状态：设计方案，待用户批准后分批实施。** 对齐 docs/04 §7 原始 Harness 概念
> （Tauri 壳 + Python sidecar + 四域沙箱）与 2026-09-21 用户产品决策：
> **订阅+快捷调用壳 + 用户数据私有化（本地数据不出端）+ 自定义本地技能**。

## 一、Harness v1.1 —— 定位与总体架构

**定位**：员工桌面端的平台「全面客户端」——订阅云端 Agent/技能并本地执行，个人数据默认
留在本机；不是第二个控制台（管理面仍在浏览器控制台）。

```text
Harness（Tauri 2 壳 + Python sidecar）
├─ 壳层（Tauri/Rust）：系统托盘、全局快捷键、通知、WebView 渲染 UI
├─ 连接层：设备绑定凭证 + Agent/技能目录订阅同步（拉取+本地缓存）
├─ 快捷调用：托盘/快捷键 → 选 Agent → 流式问答 → 结果贴回任意应用
├─ 本地数据仓（SQLite）：会话历史 / 本地记忆 / 执行审计 —— 默认不出端
├─ 技能运行时（Python sidecar）：签名技能包安装 → 四域权限提示 → 沙箱执行
└─ Permission Manager：文件系统/网络/进程/浏览器 四域策略 + HITL 确认弹窗
```

**与既有平台能力的对接点**（全部复用，零平台改造的部分已标注）：

| 平台能力 | Harness 消费方式 |
|---|---|
| Agent Registry / 配置版本层 | 订阅同步拉取 enabled Agent 目录（`GET /api/v1/agents`） |
| OpenAI 兼容端点 / SSE | 快捷调用的对话通道（流式） |
| A2A agent-card | Agent 能力名片展示（`/.well-known/agent-card.json`） |
| 技能包 + Ed25519 签名 + 附件（M34） | 本地安装 = 下载签名包 → 本地验签 → 权限提示 → 落盘 |
| SandboxRunner 沙箱模式（M33） | sidecar 技能执行同构：子进程 + rlimit + cwd 软隔离 |
| HITL 审批语义（M24） | 敏感操作（删除文件/对外发送）桌面弹窗确认，本地审计 |
| 会话/记忆 API + Memory 四层 scope（M34） | 本地模式用本地仓；云端模式走平台 API |
| 审计（observability/audit） | 本地审计留存 + 用户可选上报 |

## 二、分期计划（每期一个可验收批次）

### M37 —— 壳工程基座（先做）
1. Tauri 2 + React（复用控制台组件风格）项目脚手架，Windows 优先（Linux/macOS 后置）；
2. **设备绑定认证**：设备注册 → 平台发设备专属 API Key（ApiKey 表 + 设备名标注，
   可单独吊销 = 远程吊销地基）；不引入新认证协议；
3. Agent 目录订阅：登录后拉取目录并本地缓存（增量同步，本地 SQLite 表）；
4. **快捷调用 MVP**：托盘菜单 + 全局快捷键 → Agent 选择 → 流式问答窗 → 一键复制；
5. 验收：热键 3 秒内完成「唤起 → 提问 → 流式回答」；断网时给出明确降级提示。

### M38 —— 数据私有化（用户数据不出端）
1. **本地数据仓**：会话历史 / 本地记忆（scope=local）/ 技能执行审计 落本地 SQLite
   （Tauri sidecar 管理），默认不向平台上传任何对话内容；
2. **双模式开关**：本地模式（对话走平台推理但会话/记忆只留本地）与云端模式
   （记忆 scope=user 上行平台，用户显式开启）；企业策略可经配置强制其一；
3. **隐私清单页**：逐类数据（对话/记忆/审计/缓存）展示「存哪、谁能看、一键清除」；
4. 验收：本地模式下抓包验证无会话内容上行（仅推理请求）；隐私清单覆盖全部落盘数据。

### M39 —— 本地自定义技能
1. 签名技能包安装流：市场/文件导入 → Ed25519 验签（复用 skill_pkg）→ 附件完整性
   （M34 清单）→ **四域权限提示**（用户逐域批准）→ 本地落盘；
2. sidecar 技能运行时：skills.json 声明（入口/权限域/白名单）→ 沙箱执行
   （子进程 + rlimit + cwd 约定，对齐 M33 语义与限制，Windows 降级如实声明）；
3. 本地技能调用：快捷调用中 Agent 的技能注入（云端 Agent 声明的技能 + 本地已装技能合并）；
4. HITL：高危动作（删除/外发）桌面确认弹窗 + 本地审计记录；
5. **移动远程审批**：HITL 待办 → IM 卡片推手机 → 按钮决策回传（见 §二.5）；
6. 验收：演示技能「excel-report」安装 → 权限提示 → 沙箱运行 → 越界请求被拒 + 审计可查；手机卡片批准一个 WAITING_HUMAN 任务。

### M40（GA 候选，后置）
审计上报（企业可选）、远程吊销生效传播、离线降级（本地小模型可选项）、自动更新。

## 二.5、移动远程操作（参考 Codex / ZCode / workbuddy 等工具的远程模式）

**产品形态**：不做原生 App——手机侧优先**企业 IM（飞书/钉钉/企微）卡片**（企业已在用、
零安装），辅以**响应式移动 Web 页**（平台直接 served，设备配对后浏览器/PWA 打开）。
三类远程能力：

| 能力 | 交互 | 复用的既有平台机制 |
|---|---|---|
| **远程审批**（Codex/ZCode 的「手机批准」模式） | 桌面 Harness 遇 HITL 审批/敏感操作 → IM 卡片推送到手机 → 卡片按钮批准/拒绝（→ Action 协议回传） | M30 IM 卡片 + Action 协议（按钮 → run_action 回调链）；任务通道 WAITING_HUMAN/WAITING_INPUT 状态机 |
| **远程触发**（会话无缝切换：手机下达、桌面执行） | 手机 IM 里对 Bot 说/点卡片「新建任务」→ 任务进平台队列并路由到配对桌面 Harness 后台执行 → 完成后卡片回执结果 | 任务引擎（优先级/幂等，M32）+ schedules + IM 出站卡片（M30 D 线）+ 设备-用户绑定 |
| **远程监控**（进度/结果随手看） | 手机响应式 Web 页：任务列表/会话历史/审批待办只读视图（数据经平台 API + 设备 Key，桌面离线时显示最后状态） | conversations API + tasks API + agent-card；响应式页面复用控制台组件 |

**配对与安全**：手机 IM 身份 ↔ 平台用户 ↔ 配对桌面设备 三向绑定（设备注册时建立）；
远程指令仅限该用户配对的设备生效；远程审批等价 HITL 决策（落审计 `harness.remote.approve`）；
会话内容经 IM 传输的隐私例外须在隐私清单页明示（IM 通道可见性由企业 IM 承担）。

**分期归位**：远程审批（卡片链路最短、价值最高）→ 并入 **M39**（与 HITL 弹窗同批）；
远程触发与监控（需任务路由到设备的调度语义）→ **M40**。

**对齐说明**：Codex/ZCode 的成熟模式——后台任务 + 完成通知、分级审批（suggest/auto/full-auto
映射到 HITL 三态）、跨端会话续接（经平台会话 API 拉取）——均按上表映射到平台既有机制，
不引入新协议。

## 三、隐私边界（核心设计原则）

1. **默认本地**：对话内容、本地记忆、技能执行记录落本机 SQLite——平台只见推理请求
   （输入文本本身即对话内容，无法回避，如实声明）；
2. **显式上行**：仅用户/企业策略开启「云端记忆同步」后，记忆 scope=user 内容上行；
3. **可清除**：隐私清单页逐类一键清除（本地仓 + 云端已同步部分分别清除）；
4. **凭据最小化**：设备 Key 仅含调用所需权限，泄露可单设备吊销；
5. **技能最小权限**：四域默认全拒，安装时用户显式授权（对齐 docs/04 §7 与 M33 沙箱哲学）。

## 四、工程量与风险

- 规模：四期均为中型批次；M37 壳工程最大（全新 Tauri 工程 + 打包链）；
- 技术风险：Windows COM 自动化（Office 技能）稳定性；Tauri WebView 与控制台组件复用度；
- 依赖：无新增第三方授权风险（Tauri MIT/Apache-2.0，docs/09 选型已定）；
- 需要 Rust 工具链（构建环境一次性搭好）。

## 五、组织记忆联动 KB（L7 剩余，小批次可并入 M37 后任意时点）

**机制**：org 层高价值记忆 → 定期/手动「沉淀」为知识库文档，进入三路检索：

1. `POST /api/v1/memory/consolidate`（admin+审计）：挑选 scope=org 且 importance ≥ 阈值
   的记忆 → 按主题聚合生成/更新文档（写入专用 KB `org-memory`，可指定）→ 复用现有
   摄入管线（分块/嵌入/图谱）；
2. 沉淀文档自动带 ACL（M36 复用）：`role=* allow` + 租户过滤；
3. 幂等：同一批记忆指纹（内容 hash）防重复沉淀；原文记忆标记 `consolidated` 不再重复入选；
4. 测试：沉淀生成文档/幂等/ACL 联动/检索可见。

工程量小（1 端点 + 聚合逻辑 + 测试），建议排在 M37 之后、M38 之前插入。
