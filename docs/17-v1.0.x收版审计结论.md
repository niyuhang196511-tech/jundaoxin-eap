## 三、真修复验证（M51~M57 三个真 bug，独立复跑）

### 3.1 worker 引导缺失（M55-A，5836776）——修复正确，验证通过；**同类缺口残留（本轮【中】发现 #1）**
- 修复实况：`worker.py:51-57` init_db → `registry.bootstrap()` → 引擎启动。
- 独立验证：test_loadtest_dualproc **2 passed**（含 worker 引导回归守卫）；HA 主拓扑与 docker-compose.ha.yml 核对一致。
- **【中】残留**：独立 worker 仍缺 `workflows_svc.load_enabled()`（workflow-as-agent 在独立 worker 注册表缺失——任务通道指向 workflow-as-agent 名会 FAILED「未注册」，提交端点不校验 agent 名）、`load_plugins()`、`registry_sync.start_subscriber`（跨副本注册表广播不达 worker）。M55-A「+7 行与 lifespan 同序」表述与实况有偏差（只补了三步中的一步）。→ 登记账本候选（修复=对齐 lifespan 全部注册步骤）。

### 3.2 幂等探测失败 fail-safe（M55-B，6a7ce03）——修复正确，验证通过；**同族 fail-open 残余窗口（本轮【中】发现 #2）**
- 修复实况：`_redis_inflight_exists` 三态（异常→None）；follower 轮询仅 `exists is False` 接管，None 继续轮询到 deadline 409；反向自证用例（探测恒 None→409→calls.b==0）在位且通过。
- **【中】残余**：`_redis_mark_inflight`（SETNX）与 `_redis_get`（缓存读）异常仍吞成「可执行」结论（与「未配置」共用 None 语义）——瞬时抖动下跨副本重复执行窗口仍在，与 fail-safe 取旨（宁可 409）不一致。严格化方向=区分「未配置」与「配置但异常」两态（同 mark=None 路径 L410 注释明示的既有取舍一并评估）。→ 登记观察项。

### 3.3 冷启动竞态（M57，4fed384）——修复正确，验证通过（含审计独立 A/B）
- seed.run = IntegrityError → rollback → 整体重跑一遍（有界，第二遍仍撞=缺陷直接抛，无无限循环）；registry._persist = IntegrityError → rollback → 重查走 update 分支（两副本写同一 manifest 结果等价；极端时序重查仍 None 时 `assert` 响亮失败=单副本启动失败而非数据损坏）。
- 独立 A/B：同竞态窗口（首查 None）下修复前语义 **RED（IntegrityError）**、修复后 **GREEN（dev tenant 恰 1 行）**；PG 活体 2 线程真并发 seed.run 双成功（4 passed 含活体）。
