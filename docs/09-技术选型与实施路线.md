## 1. 技术栈基线

Python 全栈（FastAPI + React/TS）｜ 混合部署（内网私有化 + 网关可路由外部模型 API）。

| 领域 | 选型 | 理由 | 许可证/风险 |
|---|---|---|---|
| 后端框架 | FastAPI + Pydantic v2 | 异步、OpenAPI 原生、类型安全 | MIT |
| 前端 | React + TS + Ant Design；画布用 React Flow | 生态与中后台组件 | MIT |
| Agent 运行时 | 自研内核 + **LangGraph**（实现组件） | Checkpoint/HITL/子图成熟，可替换 | MIT |
| 模型网关 | 自研适配层（可嵌 LiteLLM 库） | 需要能力路由+Policy 深度定制，LiteLLM 作供应商适配库 | MIT |
| 推理托管 | vLLM（multi-LoRA） | 定制模型统一托管的事实标准 | Apache-2.0 |
| 向量库 | Milvus（起步可用 pgvector） | 规模与混合检索，pgvector 降低 M1 门槛 | Apache-2.0 / PG License |
| 图库 | Neo4j 社区版（备选 TuGraph） | 生态最好；商用注意 GPLv3，高合规场景切 TuGraph | GPLv3 / Apache-2.0 |
| 图谱管道 | LightRAG 式自研封装 | 增量更新是硬需求，避免 GraphRAG 全量重建 | MIT |
| 文档解析 | MinerU（备选 RAGFlow DeepDoc） | 版面/表格/OCR；AGPL 注意——独立进程调用规避传染 | AGPL-3.0 / Apache-2.0 |
| 消息队列 | Redis Streams + Arq（MVP）→ Kafka（演进） | 先满足 Task Engine，保留迁移位 | RSALv2/MIT |
| MCP / A2A | 官方 Python SDK | 跟随规范版本（MCP 2025-06-18、A2A 1.0） | MIT / Apache-2.0 |
| 观测 | OpenTelemetry + Langfuse(自托管) + Prometheus/Grafana | 全链路 Trace + 指标告警一体 | MIT 等 |
| 桌面 Harness | Tauri 2 + Python sidecar | 体积小、权限模型好；sidecar 跑本地工具与技能 | MIT/Apache-2.0 |
| 本地工具链 | python-docx / openpyxl / python-pptx / Playwright | Office 与浏览器自动化 | MIT/Apache-2.0 |
| 存储 | PostgreSQL 16 / Redis / MinIO | 标准企业栈 | 宽松 |
| 部署 | Docker Compose(M1) → K8s + Helm(M2) | 平滑演进 | — |

**选型原则**：凡"与差异化无强关联"的一律用成熟开源；四项差异化能力（外链嵌入、Harness、注册钩子、定制模型注册）全部自研。

## 2. 实施路线

### M1 最小可用（约 8–10 周）
- L1 网关（OIDC+APIKey+EmbedToken）、多租户 RLS
- 模型中心：≥3 供应商接入、能力路由、策略基础版、OpenAI 兼容端点
- 知识中心：多 KB + 客服 FAQ 模板、解析/分块/混合检索、Citation
- Workflow Engine + 画布（简单 Agent）、开放 API、**嵌入外链 JS SDK**
- Task 队列基础（Redis Streams）、OTel Trace 接入、基础监控看板
- **验收**：官网客服智能体 3 行代码嵌入第三方页面，答案带引用，全程可观测

### M2 平台化（约 12–16 周）
- Agent Runtime 内核（Checkpoint/HITL/长任务）、Context Engine、Memory
- **注册钩子 SDK + Agent Registry**（生命周期/健康/灰度）、LangChain 适配层
- 工具与连接器中心 + MCP Client/Server/Registry、Skill Registry（签名+审核）
- Prompt/评测/成本中心、发布门禁与环境晋升（dev→prod）
- Harness Beta（订阅同步 + 沙箱 + Office 自动化技能 3 个）
- **验收**：LangGraph 手写 Agent 一小时接入并上架；技能市场安装到 Harness 受沙箱管控运行

### M3 生态运营（约 12 周起，持续）
- A2A 1.0 对外 + 外部 Agent 纳管、专用模型注册全流程（方案 A 四层机制）、vLLM multi-LoRA 托管
- 企业连接器（下单/库存/CRM/OA/飞书/钉钉）、插件市场运营
- Harness GA（插件市场、远程吊销、离线降级）、多租户完整隔离与 DR 演练、SLO 达标（99.9%）
- **验收**：外部系统经 A2A 调用平台 Agent；自训 CV 模型注册后 10 分钟内成为可治理工具并带数据回流

## 3. 团队与分工建议（6–8 人参考）

| 角色 | 人数 | 负责 |
|---|---|---|
| 平台后端 | 2 | 控制面十中心、网关、API |

## 4. 风险清单

| 风险 | 缓解 |
|---|---|
| 范围过大、M1 失焦 | 严格按 M1 验收标准裁剪，注册钩子/Harness 坚决不进 M1 |
| KG 构建成本高 | 起步只对 2–3 个高价值 KB 开图谱；检索路由默认向量优先 |
| Harness 安全事故 | 技能默认最小权限+签名+HITL；M2 先内部灰度 |
| 外链被滥用 | EmbedToken 短时效+域名白名单+频控+行为审计 |
| 上游开源协议变化 | 关键依赖锁定版本，许可证季度复审（尤其 Neo4j/MinerU） |
| 模型供应商不稳定 | 降级链+语义缓存+本地 vLLM 兜底 |
